# 상담 종료 후 3개월 삭제

홈페이지에는 `상담 종료 후 3개월간 보관한 뒤 삭제합니다.`라고 안내합니다.
시트의 **처리 상태(J열)를 ‘상담 종료’로 변경**하는 시점에 L열 상담 종료일시와 M열
삭제 예정일시를 기록합니다. `완료`, `취소` 등 다른 상태를 종료로 추측하지 않습니다.
과거 상담을 입력할 때에는 L열에 실제 종료일시를 날짜/시간으로 입력하세요.
종료 후 다시 상담을 진행하면 상태를 바꾸고, 다시 종료할 때 ‘상담 종료’를 선택합니다.

3개월은 90일이 아닌 달력 기준입니다. 예: 1월 31일 → 4월 30일, 9월 27일 → 12월 27일.
한국 시간의 시각까지 유지합니다. 매시간 확인하여 기한이 지난 기록의 A:M 값과 셀 메모를
삭제합니다. 다른 접수 행의 위치가 바뀌지 않도록 행 자체는 남겨 둡니다.
종료일이 없거나 잘못된 경우 임의 삭제하지 않고 작업 오류로 알립니다.

## 설치 (구글 계정 소유자 승인 필요)

1. 예약 문의 시트의 확장 프로그램 → Apps Script를 엽니다.
2. `retention.gs` 내용을 추가합니다. 기존 스크립트가 있으면 지우지 말고 새 파일로 추가합니다.
3. `installBookingRetention` 함수를 한 번 실행하고 구글 권한을 승인합니다.
4. 트리거 화면에서 `bookingOnEdit`와 `purgeExpiredBookings`가 있는지 확인합니다.
5. 구분 가능한 가상 테스트 행으로 상태 변경 시 L:M 기록과 만료된 기록의 삭제를 검수합니다.
6. 검수가 끝난 뒤 Vercel의 `BOOKING_RETENTION_AUTOMATION_READY`를 `true`로 설정합니다.

설치 함수 자체는 고객 데이터를 삭제하지 않습니다. 설치 후 시간 트리거가 실제로 만료된
문의 기록을 삭제합니다. Google의 실행 지연/오류가 있으면 정각 실행을 보장하지 않으므로
Apps Script 실행 내역과 구글이 제공하는 트리거 실패 알림을 관리자가 확인해야 합니다.
스크립트나 Sheets API로 상태를 바꾸는 경우 onEdit가 실행되지 않으므로 실제 종료일시도
함께 기록해야 합니다. 잘못된 날짜/누락은 매시간 검사에서 오류로 알립니다.

스크립트는 현재 시트의 값과 셀 메모를 삭제합니다. Google의 버전 기록, 댓글, 내려받은 파일,
별도 복사본이나 플랫폼 백업까지 삭제하는 기능은 아닙니다. 고객 개인정보를 별도로 복사하거나
댓글에 남기지 말고, 이미 만든 사본과 Google Workspace 보관 정책은 관리자에게 확인하세요.
Google 버전 기록까지 포함한 영구 파기는 별도 검토가 필요하며, 이 코드를 설치했다고
모든 저장 계층에서 즉시 영구 삭제되었다고 안내하면 안 됩니다.

현재 상태: 코드 및 날짜 계산 테스트 준비 완료. 설치·구글 권한 승인·실제 자동 실행 검증은 대기 중.
